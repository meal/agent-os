## What is new since v0.2.0-rc2

- **`agentos submit --agent-cli claude-code --model SPEC`** runs the task's agent as a coding-agent
  CLI inside the microVM. The guest still has no network interface and no key; the controller
  journals every model request. `resume` rebuilds the session agent from the recorded `agent_cli`
  and recovers a lost session without credentials. The CLI binary is still not shipped (Anthropic's
  licence): you build `guest/agent-cli-py314-v1` yourself, as in v0.2.0-rc2.
- **`agentos workflow submit|resume|status|cancel|export`** runs a chain of 2 to 8 task contracts
  one after the other on one workspace; step N+1 starts from the verified result of step N.
  Every step is an ordinary task with its own contract, capabilities and limits.
  - One approval covers the whole chain and binds the jail decision, the verification profiles and
    the guest images. The model endpoint is pinned when the chain is submitted; only `workflow resume`
    refuses a changed endpoint.
  - A controller killed between or during steps resumes to exactly one task per step. A cancel whose
    task request was lost still wins on resume. A garbage-collected workspace does not break the
    hand-off to the next step. A disk or database error while building the hand-off leaves the
    chain resumable; only a hand-off that does not rebuild the verified workspace fails it.
  - `workflow export` writes a bundle with each step's base, patch and verified workspace digests;
    `chain.json` and the bundle appear together or not at all.
- **`agentos cockpit`** is a read-only terminal overview of every task and workflow. It opens the
  database read-only, never writes and never migrates it. It quits on ctrl-c, reports a missing
  terminal, and stops before drawing over a dead worker.
- **Database schema version 3.** A v2 database is upgraded in place: version 3 only adds the
  workflow tables. A database written by this build is refused by v0.2.0 controllers ("newer than
  this build supports"). v0.1 databases are still not migrated.

## Unchanged

The guest protocol is still 2, and the release image recipe is still `python-stdlib-py314-v3`,
without an agent CLI. The image is rebuilt because the guest reports the workspace version
(`agent_version`), so its digest changes with the 0.3.0 bump. No other guest, runtime or WIT source
changed since rc2.

## Known limits

- `submit --agent-cli` and `agentos workflow` are tested end to end on the fake guest. Until the KVM
  rows above are run, nothing here has been shown on a real microVM or against a live model through
  these entry points.
- No session resume after a controller crash (the task ends as "agent session lost"). Claude Code
  only; streaming is replayed from a whole response.
- A workflow runs steps strictly in sequence; there is no fan-out yet. The cockpit cannot act on
  anything.
- One model provider; x86_64 Linux only; the jail needs root and delegable cgroup v2. The host
  worker is not sandboxed.
