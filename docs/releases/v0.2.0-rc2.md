# Agent OS v0.2.0-rc2 (engine preview)

Release candidate, frozen and tagged at commit `b7d57bb`. An **engine preview**: the agent runner
is proven by the KVM tests and a live run, but is not yet exposed in the `agentos` CLI (no
`submit` option starts an agent session). The CLI behaves as in v0.1.0-rc5. Published as a GitHub
pre-release with the tarball and its `.sha256` attached.

**This replaces [v0.2.0-rc1](v0.2.0-rc1.md), which is withdrawn:** its tarball bundled the Claude
Code binary. That binary is Anthropic's, licensed "All rights reserved" and used under Anthropic's
terms, which grant no right to redistribute it. rc1's GitHub release was unpublished and deleted;
its git tag remains as a source tag only.

## The agent CLI is not shipped

The release image is `python-stdlib-py314-v3`, digest
`3f8084bc2b09e5ea0a8eab7d169e0e20f6d8b1c6db89076b74e5fdb819960263`: the py314-v2 recipe
(Python 3.14.8, linux 6.18.51 built from pinned source) at guest protocol 2, **without** any agent
CLI. To run one in the guest, build `guest/agent-cli-py314-v1` yourself (see its README): that
build downloads Claude Code 2.1.295 from npm and checks it against the pinned sha256 in
`agent-cli.lock` on your machine, so the binary is never redistributed from this repository. A
test fails if `release.sh` ever defaults to an image that carries the CLI.

## What is new since v0.1.0-rc5

- **An external coding-agent CLI can run inside the microVM as the task's agent** (engine level).
  The guest still has no network interface and holds no key. A loopback proxy in the guest
  forwards the CLI's model requests over vsock; the controller turns each into a journaled,
  capability-checked `ModelCall` with the key added on the host. The CLI works on a scratch copy
  of the workspace; its changes return as a diff through the existing patch checks and the
  protected verification. A controller crash mid-session fails the task as "agent session lost"
  (no resume). New capability `agent.session`; new effect kind `run_agent_session` with its own
  lease class; recovery and crash-matrix coverage.
- **Guest protocol 2** (`RunAgent`, `ModelRequest`, `ModelReply`, `AgentDone`). **This breaks the
  v0.1 images**: a v0.2 controller refuses every protocol-1 image. Use a v0.1.0-rc5 controller for
  the old ones.
- **Message codec** for the live API: beta-only fields are stripped, `system`-role messages merged
  into the user message, `max_tokens` clamped, the model rewritten to the controller's, and
  thinking blocks replayed with their signatures. Two of these were found by the live API.

## Known limits

- The agent runner is not reachable from the `agentos` CLI yet; tests and the acceptance harness
  start it, and the agent image is yours to build.
- No session resume after a controller crash. Claude Code only (no Codex); subscription logins
  cannot work without a network. Streaming is replayed from a whole response.
- The live agent run needed three attempts (two API rejections, fixed) and used 7 model requests.
- The fresh-host gate ran in a fresh container on the only KVM host available.
- One model provider; x86_64 Linux only; the jail needs root and delegable cgroup v2. The host
  worker is not sandboxed.
- The request files of the live-run bundle (which hold the agent CLI's system prompt) were
  committed once and removed from the tree; they remain in the history of `main`.
- One timing test (`a_readable_job_is_waited_for_until_its_own_lease_plus_grace_…`) failed once in
  an incomplete run and passed in 13 reruns and in every gate run since; the cause is unknown.
