# Phase 4 Real Agent Workflow Implementation Plan

Current status (2026-10-04): historical implementation plan. Model workflow implementation
and offline regression coverage are present; live-provider acceptance remains open.
Current execution and reliability policy are tracked in [v0.1 completion](2026-10-04-v01-completion.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real language model (Anthropic Messages API, `claude-opus-5-5` by default) drives the existing `Agent` seam and fixes the fixture repository through the broker, inside the contract's limits, with every model call, file listing and file read journaled as an effect (`intend -> dispatch -> execute -> store_result -> register_result -> complete`), the verification evidence collected by the trusted profile only, a crash at any boundary neither replaying a completed model call nor double-spending the budget (a lost call is *forfeited*: FAILED, its reservation `Uncertain`, the agent asks again under a new reservation), reads served from a host-side shadow workspace validated by digest, the API key reaching nothing but the provider, and the deterministic `FakeAgent` staying the offline path — while `docker compose run --rm test cargo test --workspace` stays green and makes no network call.

**Architecture:** `agentos-core` gains three effect kinds (`ModelCall { model, turn }`, `ListFiles { turn }`, `ReadFile { path, turn }`), the `model.request` capability, the `ForfeitThenRetry` policy and the per-kind model reservation; `agentos-store` gains `Db::forfeit_effect`. `agentos-engine` gains `model/` (the `ModelProvider` trait with `AnthropicProvider` (reqwest, exactly one send per attempt), `FakeProvider` scripted from `fixtures/transcripts/*.json` keyed by conversation depth, a `Recording` wrapper, and `ModelExecutor`, which retains every response under `<home>/model/` before returning so recovery publishes it instead of re-sending), `shadow.rs` (`ShadowReader`: snapshot plus the journal's completed patches, accepted only at the task's digest), `routing.rs` (`RoutingExecutor<J>` dispatching by kind so `steps.rs`/`recover.rs` stay generic), `Decision::Forfeit`/`Attempt::Forfeited` in recovery, `ModelAgent` behind the unchanged sync `Agent` trait, and runner `act()` arms for the three new actions. The CLI gains `submit --model anthropic:<model>|fake:<transcript>`, `--api-key-file`, `--anthropic-base-url`, records `Submitted.model`, builds the agent from that record, and forwards only `PATH` and the explicit `AGENTOS_TEST_*` switches to the supervisor (`env_clear`).

**Tech Stack:** Rust 1.98.1 (`rust:1.98.1-bookworm`), edition 2024, tokio 1.53.1 (workspace pin; 1.53.x current), serde 1.0.229 / serde_json 1.0.151 (sorted-key `Map`, `preserve_order` must stay off: it is the canonical-request mechanism), **reqwest 0.13.5** (`default-features = false, features = ["rustls"]`; verified current on crates.io 2026-10-03, updated 2026-09-08), rustix 1.1.5, rusqlite 0.40.2, Anthropic Messages API `POST /v1/messages` with `anthropic-version: 2023-06-01`, default model `claude-opus-5-5` (forced `tool_choice` `any`/`tool` is rejected with 400 on it; `tool_choice: {type: "auto", disable_parallel_tool_use: true}` and `strict: true` tools are used instead; thinking is always on and its blocks must be echoed back unchanged, so the history is append-only). Re-check with `cargo search reqwest --limit 1` before pinning; never send the user's email or any identity in any request.

**Spec:** `docs/superpowers/specs/2026-10-03-phase-4-real-agent-workflow-design.md` (owner-approved decisions 1-6; parent `Agent_OS_v1_Build_Plan.md` Phase 4). Format and rigor reference: `docs/superpowers/plans/2026-10-02-phase-3b-1-firecracker-worker.md`.

## Spec deviations

Each is a place where the spec, read against the code on `main` (`a27cd58`), is infeasible or would break an invariant; the plan follows the stated resolution. **The owner must accept these before Task 1 starts** (they are small; 1, 2 and 3 are the ones that matter).

1. **`turn` is part of the new effect kinds.** `Db::record_intent` derives `EffectId` from `(task, step, kind, request_digest)` and, for a kind that consumes a tool action, also looks the intent up at `step - 1` (the retry window). A `ModelCall` consumes no tool action and journals no task event, so two model calls with identical request bytes at the same step (the retry after `ModelCallLost`, or after a 4xx) would collide and return the first, finished record instead of a new effect with a new reservation; `ListFiles` twice in a row would collide through the `step - 1` window. **Resolution:** `EffectKind::ModelCall { model: String, turn: u32 }`, `ListFiles { turn: u32 }`, `ReadFile { path: String, turn: u32 }`, where `turn` is the agent turn number the runner journals; `EffectId::derive` hashes `model`, `path` and `turn` as it hashes `expected_base`. The request digest of a `ModelCall` stays the digest of the body blob (so recovery and export find the body by it).
2. **`std::env::remove_var` is `unsafe` in edition 2024 and the repository has no `unsafe`.** **Resolution:** the key is never removed from the controller's environment; instead no child ever inherits it: `SupervisedExecutor::launch` gains `env_clear()` + `PATH` + `extra_env` (what `fixture.rs`, `guestlink.rs` and `firecracker.rs` already do), and the CLI forwards only the `AGENTOS_TEST_*` switches (with `AGENTOS_TEST_WORKERS=1`) explicitly. The residual: `/proc/<controller pid>/environ` holds the key for the life of a `submit`/`resume` given `ANTHROPIC_API_KEY`, readable by a same-UID host-worker check; `--api-key-file` has no such residual and the README recommends it. The environment-dump test asserts the key is absent from the supervisor's and the worker's environments (not the controller's).
3. **Budget and capability gates live in the runner, not the agent.** The spec's "request again only if the budget check passes" cannot be done by `ModelAgent` (it has no store access). **Resolution:** `ModelAgent` asks again after `ModelCallFailed`/`ModelCallLost`; the runner's `intend` reserves one model request and a `BudgetExceeded` ends the task with `budget exhausted` exactly as `apply_patch` does today; a missing `model.request` grant fails the task with `capability model.request not granted` at the first call (a pre-check like `ensure_snapshot`'s), never a loop of denials.
4. **Counts.** The scripted transcript makes one model call per tool use: list, read, patch, verify (fail), patch, verify (pass) = **6** settled model requests, not 4 (the `finish` call never happens: `VerifyPassed` makes the task terminal and the loop stops before asking the agent). In the crash matrix an `AfterDispatch` forfeit row sees **1** provider send (the first attempt never reached the provider) and 2 `model_call` effects (1 forfeited, 1 completed; `uncertain_model_requests == 1`); `DuringExecute` sees 2 sends.
5. **The model crash rows get their own matrix file** (`crates/agentos-engine/tests/model_crash_matrix.rs`, a `World` with `ModelAgent` + `FakeProvider` + `RoutingExecutor`) instead of extending `crash_matrix.rs::KINDS`, whose `Summary` and `expected_executions` assume one effect per kind and the fake agent. The CLI's `crash.rs::KINDS` does gain the three tags (`--crash-at after-dispatch:model_call`).
6. **`read_file` existence is checked against the current revision**, not the snapshot manifest: a file the model created with `apply_patch` is readable. The runner pre-check is syntactic (relative, no `..`, no excluded component, no NUL); the `ShadowReader` refuses what is not a regular file of the rebuilt shadow, or crosses a symlink.
7. **Reads retain nothing.** A crash after a `ListFiles`/`ReadFile` executed (`DuringExecute`, `AfterExecuteBeforePublish`, `AfterBlobPut`, `AfterRegister`) is `Decision::Redispatch` (lease 2, the read runs again, same bytes), not `PublishRetained`: reads are idempotent host-side reads and the receipt machinery of `jobs/` would be ceremony. `ModelCall` *does* retain (`<home>/model/`), as the spec requires.
8. **`ModelProvider::complete` returns a boxed future** (`Pin<Box<dyn Future<Output = ProviderResult> + Send + '_>>`) so the CLI can hold `Box<dyn ModelProvider>` chosen at run time; `Executor` keeps its RPITIT shape.
9. **Only contracts that call the model gain `model.request`.** The fixture contract helpers of the existing tests (4 capabilities, 4 handles, `model_requests: 1`) are asserted all over the suites; they stay. New helpers (`contract_model`, `Cli::model_contract`) and the README example carry the fifth capability.

- Use `docker compose` for every build, test and script (`docker compose run --rm test …`; KVM tier `docker compose run --rm test-kvm …`; the `test` service is unchanged). **Default `cargo test` makes no network call:** every provider test talks to a `127.0.0.1` server the test starts (`common::http`), `FakeProvider` reads files, and the live test is gated. The compose services and the Dockerfile do not change (if `aws-lc-sys`, pulled in by reqwest's `rustls` feature, fails to build in `rust:1.98.1-bookworm`, add `cmake` to the Dockerfile's `apt-get install` line in Task 4 and say so in the task report; on x86_64 Linux it normally builds with the image's gcc alone).
- Check the latest library versions online before pinning and record them (above: reqwest 0.13.5, tokio 1.53.x, serde_json 1.0.151 were current on 2026-10-03; Rust toolchain 1.98.1). The implementer re-runs `docker compose run --rm test cargo search reqwest --limit 1` before Task 4 and updates the pin here if it moved. `cargo search` only; no request carries the user's email or any identity.
- Commits carry **no** `Co-Authored-By` trailer. Each task ends in one commit with the exact message given. Always write the failing tests first, run them, implement, run again, and verify before committing.
- The repository has no `unsafe`: `std::env::set_var`/`remove_var` are never called (Spec deviation 2); test-only environment is passed with `Command::env`/`with_env`.
- **Exactly one HTTP send per attempt.** `AnthropicProvider` builds a `reqwest::Client` with no retry layer, sends once, and maps the result: 2xx ⇒ `Response`, any other status received ⇒ `Rejected` (settled failure, counted), no status (connect, timeout, EOF mid-body) ⇒ `Transport` (unresolved ⇒ forfeited, counted as uncertain). Nothing in the engine ever re-sends under the same reservation; a `ModelCall`'s lease generation is 1 forever (never `Redispatch`).
- Names, constants and strings are the spec's: capability name `model.request`; tags `model_call | list_files | read_file`; artifact types `model-request` (the body, registered unlinked before the turn, linked to the effect after the intent), `model-response`, `file-list`, `file-content`; headers `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`; `ANTHROPIC_BASE_URL = "https://api.anthropic.com"`; `DEFAULT_MODEL = "claude-opus-5-5"`; `READ_LIMIT: usize = 64 * 1024` (`truncated: true` past it); `MODEL_TIMEOUT: Duration = 600 s` (bounded by the task deadline); `PROVIDER_TEXT_LIMIT = 4096` bytes of an error body kept (then `guest_text`-escaped and cut to 512 for the reason string); retention path `<home>/model/<effect_id>-<attempt_id>/response.json` (atomic write, `job::atomic_write`); shadow path `<home>/tasks/<task>/shadow`; journal event `EffectForfeited` (reserved); `Decision::Forfeit`; failure reasons `transport failure: …`, `http <status>: <body excerpt>`, `malformed model response: …`, `no model provider configured`, `shadow workspace digest mismatch: expected <d>, found <x>`, `file not in the workspace: <path>`, `path <p> crosses symlink <l>`, `path excluded from the workspace digest: <p>`; task failure reasons `capability model.request not granted`, `budget exhausted`, `agent finished without verified success`; CLI usage texts `--yes needs --fake-agent-patch FILE or --model anthropic:<model>|fake:<transcript>`, `no API key: pass --api-key-file FILE or set ANTHROPIC_API_KEY`, `unknown model spec {s:?}; expected anthropic:<model> or fake:<transcript file>`.
- Every task leaves `docker compose run --rm test cargo test --workspace` green with no KVM, no network and no privilege beyond the container's own. Gated tests print `SKIPPED: …` and return when their switch is unset, and **panic** when it is set but unusable (`kvm::require` style): `live::require()` for `AGENTOS_LIVE_MODEL_TESTS=1`.
- Test environment variables, each honoured only together with `AGENTOS_TEST_WORKERS=1`: the 3b-1 set unchanged; the CLI forwards every variable named `AGENTOS_TEST_*` to the supervisor (Task 9). ## Review Focus

An adversarial reviewer should attack these five; each names the test that pins it in the owning task.

- **Request bytes that differ between the live run and the replay.** Any nondeterminism (map order, a timestamp, a tool-use id generated locally, the body of a lost call differing from its retry) surfaces as `NondeterministicAgent` and fails the task. Tests: `same_observations_give_identical_request_bytes_and_digest`, `request_bytes_have_sorted_keys_and_no_volatile_fields` (Task 6), `every_model_row_replays_without_divergence_and_never_redispatches_a_model_call` (Task 8).
- **A model call billed twice.** A lost response must become a forfeit (new effect, new reservation, old one `Uncertain`), a retained response must be published without a second send, and a `ModelCall` must never be re-dispatched under lease 2. Tests: `transport_failure_forfeits_and_counts_as_uncertain` (Task 7), `model_after_execute_before_publish_publishes_the_retained_response_without_a_second_send`, `model_during_execute_forfeits_and_counts_the_lost_send_as_uncertain`, `every_model_row_replays_without_divergence_and_never_redispatches_a_model_call` (Task 8), `forfeited_model_request_stays_counted_as_uncertain` (Task 2).
- **The key leaking.** It must appear in no event, blob, artifact, `Submitted` row, export, log line, `Debug` output, job directory, or child environment. Tests: `api_key_debug_is_redacted` and `provider_errors_never_quote_the_key` (Task 4), `supervisor_environment_holds_only_path_and_the_explicit_extras` (Task 9), `api_key_reaches_only_the_provider_and_never_the_journal_blobs_home_or_job_environments` (Task 10).
- **Reads that lie about the revision.** `read_file`/`list_files` must show exactly the journaled revision: a shadow that drifted (tampered, or a patch completed under a pending cancel) is rejected, never served; a traversal, an excluded path or a symlink crossing never reaches the host. Tests: `reads_see_the_patched_revision`, `a_tampered_shadow_is_rebuilt_and_a_journal_mismatch_is_rejected`, `read_file_refuses_traversal_excluded_and_symlink_paths` (Task 5).
- **Model-controlled strings reaching host paths, logs or the journal unbounded.** Tool inputs (`path`, `patch`), `stop_reason`, text blocks and provider error bodies are data: validated, bounded (`guest_text`), placed in JSON only. Tests: `hostile_tool_inputs_are_data_and_never_touch_host_paths` (Task 7), `provider_error_bodies_are_bounded_before_they_reach_the_journal` (Task 4), `read_file_refuses_traversal_excluded_and_symlink_paths` (Task 5).
